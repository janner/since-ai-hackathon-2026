# Evaluation 3074: the project's own labels, not ground truth

`docs/decisions.md` D15: without ground truth a recall figure would be circular. This set is the
project's own reading of 21 notices from the IFIC 3074 slice. It is not Traficom's judgement, and
no accuracy or recall claim against Traficom follows from it.

## What is labelled

The 21 notices in the 7 Nov 2026 slice run that reached G3 and received a class: 11 `exceeds`,
5 `near`, 4 `not_space` and one `cannot_decide`; no case in this slice is `clear`. The run file is
`out/3074_results.csv` (input sha256 `a9755213b6cdb7a26a1ca1dcf95ba69a362d3bcc2cb088e91b6b8e01e4790e31`,
rules 1.1.0). Labels and one-line reasons are in `docs/eval-3074.csv`.

The other 175 notices were dropped at G1 (155: no band overlap) or G2 (20: below the horizon or
never visible). The run makes no class claim about them, so they are outside a class agreement;
their counts stay in `out/funnel.json` and are covered by the pipeline tests.

Six cases appear under two notice ids with identical satellite, band and margin
(`95500027`/`322500245`, `103500416`/`303500416`, `103500417`/`303500417`,
`119500051`/`319500051`, `109500876`/`309500876`, `124520179`/`324520179`). Each notice is a row:
the run decides each notice on its own (D16), and `103500417`/`303500417` differ only in `st_cur`.

## Label rule

The rule is the analyst's, deliberately not the classifier's:

| Label | Rule |
|---|---|
| `exceeds` | margin > +3.0 dB |
| `near` | −3.0 dB ≤ margin ≤ +3.0 dB |
| `clear` | margin < −3.0 dB and every part of the notified band carries a Finnish satellite downlink allocation (space-to-Earth) |
| `not_space` | margin < −3.0 dB and some part of the notified band has no Finnish satellite downlink allocation |
| `cannot_decide` | a required term (power, gain, limit row, orbit or perigee) is missing, so no margin exists |

A hot margin outranks the allocation finding, as in the tool: a band with no Finnish satellite
downlink allocation still reads `exceeds` or `near` when the upper bound is above the limit, and
`not_space` only when the margin is also cold.

The per-sub-band reading is D18: a notice at 3 625-4 200 MHz covers MOBILE AND FIXED from
3 625 to 3 800 MHz, so the whole notice is a finding even though 3 800-4 200 MHz carries FSS.
The first label pass used a whole-band reading; the two HISPASAT-5 rows were corrected to
`not_space` when the rule was applied, before the agreement was recomputed. The run was not changed
to fit the labels: it already classed both notices `not_space` under D18.

The decision band is ±3 dB rather than the tool's 0 dB because the PFD is an upper bound: the
notice's peak gain is aimed at every territory point, there is no I/N, no receiver noise figure
and no bandwidth term (README known limit 1). An upper-bound overage below 3 dB is not a
decision-grade exceedance; it is a case to look at. On this set the rule moves five rows from
`exceeds` to `near`; all five stay in the queue either way (both classes are queued). The only
effect is the class and the letter set (11 `exceeds` letters in the run, 6 under these labels).

```
  cannot_decide   1   1

differences (5):
  95500027     run=exceeds       own=near          margin=   0.82  ...
  119500051    run=exceeds       own=near          margin=   1.65  ...
  124520184    run=exceeds       own=near          margin=   1.74  ...
  319500051    run=exceeds       own=near          margin=   1.65  ...
  322500245    run=exceeds       own=near          margin=   0.82  ...
```

The five differences are three notices (two of them duplicated) between +0.82 and +1.74 dB. They
are not missed cases: both classes are in the run's queue. They are the boundary where the
screening's "above zero" and the analyst's "clear enough to act on" disagree.

No other label differs: all five `near`, all four `not_space` and the one `cannot_decide` agree
with the run.

## Reproduce

```
uv run python -m app.pipeline --ific data/itu-ific-3074/ific3074.mdb \
    --register data/frequencies_of_interest.csv \
    --m4 data/taajuusjakotaulukko.json --out out/
uv run python scripts/eval_3074.py
```

The run needs `data/`, which is fetched by `scripts/fetch_data.py` and never committed. The script
reads any run CSV with the same columns; `--run` and `--labels` override the defaults.

## Limits

- These are own labels, not Traficom ground truth. Agreement is a consistency check against one
  documented reading, not validation and not an accuracy figure.
- One analyst wrote the labels and chose the 3 dB band with the run in view. There is no second
  annotator, so no inter-annotator agreement exists.
- The labels were revised once: the two HISPASAT-5 rows moved from `clear` to `not_space` when the
  per-sub-band M4 rule (D18) replaced the whole-band reading. The five remaining differences are
  the ±3 dB boundary, not the M4 rule.
- The set covers the 21 notices the run classified in this slice. It says nothing about the
  155 G1 drops beyond what the funnel counts and tests already cover.
- The labels attach to this run's input digest. A new IFIC or a changed table can change a margin;
  re-label before comparing a different run.
